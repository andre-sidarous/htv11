# Data model

Source of truth: `supabase/migrations/*.sql`. TypeScript mirror: `src/lib/types/database.ts`. Change both in the same PR, and tag the team.

```
auth.users ─1:1─ profiles ─┬─< jams (host_id)
                           ├─< jam_members >─ jams           unique (jam_id, user_id)
                           │       ├─< live_locations         unique (jam_id, user_id), FK → jam_members
                           │       └─< health_signals         FK → jam_members
                           ├─< alerts (affected_user_id) >─ jams
                           │       ├─< alert_responses        unique (alert_id, user_id, kind)
                           │       ├─< incident_packages
                           │       └─< notification_events (alert_id, nullable) >─ jams
                           └─< trusted_contacts (owner_user_id)
storage: recordings (private bucket, objects under {user_id}/...)
```

## Tables

| Table | Purpose | Key constraints |
|---|---|---|
| `profiles` | Display name, optional phone, avatar, `checkin_buffer_seconds` (30 to 1800, default 120: how long a check-in waits before the group alert). Created in profile setup (**no trigger**). | PK refs `auth.users`, display_name 1 to 60 chars |
| `jams` | A trip. `join_code` and `ntfy_topic` are generated by DB defaults. | `travel_mode` walking/transit/mixed. `status` waiting/active/ended (ended requires `ended_at`). Delays 5 to 3600s |
| `jam_members` | Membership, role, **five consents (all default false)**, `emergency_preference` (nullable, no default). | unique (jam_id, user_id) |
| `live_locations` | One latest row per member, **upserted** on (jam_id, user_id). | FK to jam_members, lat/lng range checks |
| `health_signals` | Simulated readings. | `source = 'simulated'` only |
| `alerts` | Risk score, severity, status, `escalation_state`, `reasons` (jsonb array), `next_deadline_at`. | **Partial unique: one open alert (`resolved_at is null`) per (jam_id, affected_user_id).** RESOLVED/CANCELLED require `resolved_at` |
| `alert_responses` | seen / acknowledged / responding / safe. | unique (alert_id, user_id, kind) |
| `trusted_contacts` | Contacts and what they may receive (all default false), confirmation status. | Owner-only |
| `incident_packages` | Snapshot for an alert, recipients (jsonb), `access_token_hash`, retention, expiry, soft delete. | retention 1 to 720h |
| `notification_events` | Log of ntfy / sms_preview / in_app / voice_call / sms attempts ("last notification sent"). | Written by the server only. Never stores phone numbers. |

View `member_profiles` returns `(id, display_name, avatar_url)` for you and anyone you share a Jam with. Use it for co-member names, because `profiles` itself is own-row-only.

## RPCs

| Function | Use |
|---|---|
| `join_jam(code text) → uuid` | Join by code (case and whitespace are ignored). Reactivates you if you left. Errors: `not_authenticated`, `profile_required`, `invalid_code`, `jam_ended`. |
| `delete_incident_package(p_id uuid) → text` | Soft-deletes and wipes the payload. Returns the recording path to remove. |
| `is_jam_member(p_jam_id)`, `is_active_jam_member(p_jam_id)` | Policy helpers. Also callable from the client. |

## RLS summary

| Table | Read | Write |
|---|---|---|
| profiles | own row | insert/update own |
| member_profiles (view) | self + co-members (no phone) | none |
| jams | host + members | host inserts (`host_id = you`). Host updates non-identity columns. **Join only via `join_jam`.** |
| jam_members | co-members | host inserts own host row. You update **only** your consent/preference/`is_active`/`left_at` (column grants block role changes). |
| live_locations | yourself, plus **active** members when that member has `location_consent` and `sharing_enabled` | your own row, with location consent, while the Jam is `active` |
| health_signals | yourself, plus active members when that member has `health_consent` | your own, with health consent |
| alerts | members | active members insert/update (POC: the risk engine runs on the client) |
| alert_responses | members of the alert's Jam | insert as yourself |
| trusted_contacts | **owner only** (phone numbers never visible to Jam members) | owner only |
| incident_packages | affected user + listed member recipients, not deleted, not expired | members of the alert's Jam insert. Delete via RPC. External contacts go through an Edge Function (`incident-access`). |
| notification_events | members | Edge Functions (service role) only |
| storage `recordings` | owner (`{user_id}/` prefix) | owner |

`anon` has no table access. The service role bypasses RLS and is used only inside Edge Functions (`supabase/functions`), never in the app.
These rules were exercised with automated checks (as host, member, affected user, and outsider) against the migrations before merge.
